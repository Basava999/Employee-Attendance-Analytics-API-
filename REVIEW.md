# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` L73-74 | Always returns `{"status":"ok"}` without pinging MongoDB. A downed DB still reports healthy. | Start the app with MongoDB stopped; `GET /health` still returns 200 instead of 503. | Replaced with `client.admin.command("ping")` wrapped in a try/except that raises `HTTPException(503)` on failure. |
| 2 | `MongoClient()` L22 | Client created without `tz_aware=True`. All returned datetimes are naive (no timezone), causing silent timezone bugs throughout. | Read a document: `punch_in.tzinfo` is `None`. Any arithmetic with UTC-aware datetimes raises `TypeError`. | Added `tz_aware=True` and `serverSelectionTimeoutMS=5000` to the `MongoClient` constructor. |
| 3 | Global / startup | No indexes created at startup. No unique constraint on `emp_code`; no compound unique on `(emp_code, date)`. | Two concurrent `POST /employees` with the same `emp_code` both succeed (data corruption). Attendance queries do full collection scans. | Added `@app.on_event("startup")` that creates four indexes idempotently with explicit `name=` parameters and error logging. |
| 4 | `create_employee()` L79 | Check-then-insert race condition: `find_one()` then `insert_one()` allows two concurrent requests with the same `emp_code` to both succeed. | Fire two identical POST /employees at the same instant — both return 201. | Removed the `find_one()` check entirely. Rely on the unique index `{emp_code:1}` and catch `DuplicateKeyError` → 409. |
| 5 | `create_employee()` L82 | `datetime.now()` returns a **naive** datetime in the server's local timezone, not UTC. | On a server in IST, `created_at` is stored 5:30 ahead of the correct UTC value. Compare against epoch-ms — it's wrong. | Replaced with `utc_now_truncated()` which uses `datetime.now(tz=UTC).replace(microsecond=0)`. |
| 6 | `create_employee()` L85 | Returns `created_at` as a raw Python datetime object instead of epoch milliseconds as required by the contract. | API response shows `"created_at": "2026-07-06T04:30:00"` (an ISO string) instead of `1783312500000` (integer). | Added `format_employee()` helper that converts `created_at` to epoch ms via `dt_to_epoch_ms()`. |
| 7 | `EmployeeIn` model L53-60 | No validation at all: `emp_code` can be any string, `email` is unchecked, `shift_start == shift_end` is allowed, `joined_on` can be `"2026-02-30"` (invalid date), `name` and `department` have no length constraints. | `POST /employees {"emp_code":"BAD","name":"","email":"notanemail","department":"","shift_start":"09:30","shift_end":"09:30","joined_on":"2026-02-30"}` returns 201 instead of 422. | Replaced with `EmployeeCreate` model with full Pydantic v2 validators: `emp_code` regex `^EMP\d{4,6}$`, email regex and length, shift time HH:MM pattern, `shift_start != shift_end`, `joined_on` parsed as real date, name 1-100, department 1-50. |
| 8 | `list_employees()` L93 | `skip = page * page_size` — off-by-one error. Page 1 skips `page_size` records, so the first page is always empty. | `GET /employees?page=1` returns no items even when employees exist. | Corrected to `skip = (page - 1) * page_size`. |
| 9 | `list_employees()` L94 | `total = db.employees.count_documents({})` always counts the entire collection, ignoring the department filter. | With 3 Engineering + 2 Sales employees, `GET /employees?department=Sales` returns `total: 5` instead of `2`. | Changed to `count_documents(q)` using the same filter dict as the find query. |
| 10 | `list_employees()` L95 | No `.sort()` — results are in arbitrary MongoDB insertion order. Paging is non-deterministic. | Repeated `GET /employees?page=1&page_size=2` calls return different orderings. Contract requires `emp_code` ascending. | Added `.sort("emp_code", ASCENDING)`. |
| 11 | `list_employees()` L89 | No bounds validation on `page` or `page_size`. `page=0`, `page=-1`, or `page_size=500` all accepted. Contract says `page >= 1`, `page_size` 1-100. | `GET /employees?page_size=101` returns 200 instead of 422. | Changed to `Query(default=1, ge=1)` and `Query(default=20, ge=1, le=100)`. |
| 12 | `punch_in()` L101 | No employee existence check before dereferencing. `emp = db.employees.find_one(...)` can be `None`, then `emp["shift_start"]` → `TypeError` → **500**. | `POST /attendance/punch-in {"emp_code":"EMP9999"}` gives a 500 Internal Server Error. | Added explicit `if emp is None: raise HTTPException(404, "Employee not found")`. |
| 13 | `punch_in()` L102 | `if body.punched_at` uses Python truthiness — `0` is falsy. So `punched_at: 0` is treated as "omitted" (use current time) instead of being rejected as out-of-range. | `{"emp_code":"EMP0001","punched_at":0}` silently uses current time instead of returning 422 for an out-of-range value. | Changed to `if body.punched_at is not None`. Added `StrictInt` type with range validation in the Pydantic model. |
| 14 | `punch_in()` L102 | `datetime.fromtimestamp(ms/1000)` returns a **naive** datetime in the server's **local** timezone, not UTC. On an IST server, the stored BSON date is 5:30 hours off. | Punch-in at `1783312500000` (2026-07-06T04:35:00 UTC) stores as `2026-07-06T10:05:00` (IST interpreted as UTC). | Replaced with `epoch_ms_to_utc_dt()` which truncates to whole seconds and creates a UTC-aware datetime via `datetime.fromtimestamp(sec, tz=UTC)`. |
| 15 | `punch_in()` L102 | `datetime.now()` as fallback — naive, local time. Same timezone issue as #14. | The "default to current time" path stores the wrong UTC instant. | Replaced with `utc_now_truncated()`. |
| 16 | `punch_in()` L103 | `d = ts.date().isoformat()` — uses the date of the naive timestamp in whatever timezone the server is in. Should be the IST calendar date, with overnight shift exception per R1. | For an overnight shift (22:00-06:00), a punch-in at 02:00 IST on July 7th should give date `2026-07-06` (the previous day's shift), but instead gets `2026-07-07`. | Replaced with `compute_attendance_date()` which converts to IST, checks overnight shift conditions, and applies the previous-day rule. |
| 17 | `punch_in()` L104 | Check-then-insert race: `find_one()` then `insert_one()` — two concurrent punch-ins for the same (emp_code, date) can both succeed. | Fire two simultaneous `POST /attendance/punch-in` for the same employee — both return 201. | Removed `find_one` check. Rely on unique compound index `{emp_code:1, date:1}` and catch `DuplicateKeyError` → 409. |
| 18 | `PunchInIn` / `punch_in()` L66/109 | `status` is an unchecked `str`. Allows `ABSENT`, `LEAVE`, or any arbitrary value. Contract says only `PRESENT`, `WFH`, `ON_DUTY`. | `{"emp_code":"EMP0001","status":"ABSENT"}` creates an ABSENT record via punch-in, which should be impossible. | Added a `@field_validator("status")` that rejects anything not in `PRESENCE_STATUSES`. |
| 19 | `punch_in()` L119 | `doc["id"] = str(res.inserted_id)` — leaks an `id` field in the response. Contract says no `_id` or `id`. | Response contains `"id": "66a..."` which should not be there. | Removed. Use `format_attendance_record()` which excludes `_id`. |
| 20 | `punch_in()` | No epoch-ms validation. Accepts floats (`1.5`), strings (`"123"`), booleans, and seconds-scale values (`1609459200` which is < 100 billion). Pydantic v2 lax mode coerces silently. | `{"emp_code":"EMP0001","punched_at":1609459200}` (seconds, not ms) is silently accepted. | Used `StrictInt` in the Pydantic model with a range validator `[100000000000, 4102444800000]`. |
| 21 | `compute_late_minutes()` L35 | `start = punch_in.replace(hour=h, minute=m)` — anchors `shift_start` on the punch-in's clock (which is UTC), not on the IST attendance date. For a 09:30 IST shift, it creates 09:30 **UTC**, which is 4 hours off. | EMP0001 punched in at 03:58 UTC (09:28 IST, within grace). The starter computes `03:58 UTC - 09:30 UTC = -5h32m = -332 min`, which is negative and returns 0 by accident. For a punch-in at 10:05 UTC (15:35 IST), it gives `10:05 - 09:30 = 35 min > 10`, returns 35 — correct by accident but for the wrong reason. | Rewrote: `anchor_shift_datetime()` creates shift_start on the **attendance date in IST**, converts to UTC, then computes elapsed seconds correctly. |
| 22 | `compute_late_minutes()` | No overnight shift handling. For a 22:00-06:00 shift, anchoring shift_start on the punch-in's date gives completely wrong results. | Overnight shift employee punches in at 21:55 IST — should be 0 min late, but the starter's logic breaks entirely. | `anchor_shift_datetime()` uses the attendance date (which already accounts for overnight via `compute_attendance_date`). |
| 23 | `compute_late_minutes()` | No sub-second truncation. `09:40:00.900` should be treated as `09:40:00` (0 late), but the fractional second makes the elapsed > 600s → late. | Punch-in at exactly 09:40:00.900 IST for a 09:30 shift — the 0.9s makes it 600.9s > 600, so it's wrongly marked late with `late_minutes=10`. | All instants are truncated to whole seconds at ingestion via `epoch_ms_to_utc_dt()` (divides ms by 1000, floors). |
| 24 | `compute_work_hours()` L41 | Uses Python `round()` which is banker's rounding (round-half-to-even). Contract requires half-up. | 450 seconds = 0.125 hours. `round(0.125, 2)` → `0.12` (banker's rounds to even). Half-up should give `0.13`. | Replaced with integer arithmetic: `hundredths = (sec*200+3600)//7200; work_hours = hundredths/100`. |
| 25 | `compute_overtime()` L46 | `datetime.fromisoformat(date_str).replace(hour=h, minute=m, tzinfo=IST)` — `fromisoformat("2026-07-06")` returns a naive date, `.replace(hour=...)` fails or gives wrong results. Also no overnight shift handling (shift_end on next day). | For overnight shift 22:00-06:00 with punch-out at 06:40 IST on July 7th, the shift_end should be 06:00 on July 7th. The starter anchors on the date string which is July 6th → 06:00 July 6th → negative overtime calculation. | Rewrote with `anchor_shift_datetime()` that adds a day for overnight shifts. |
| 26 | `compute_overtime()` L47 | No 30-minute minimum threshold. `max(0, int(...))` returns any positive minutes. Contract says overtime only when >= 30 minutes. | Punch-out 5 minutes after shift_end → overtime=5. Should be 0 (under 30-minute threshold). | Added threshold check: `if minutes < 30: return 0`. |
| 27 | `list_attendance()` L144 | `docs = list(db.attendance_logs.find(q))` — loads the **entire matching set** into memory. On 100k records with no filters, this downloads all docs into Python. | With 100k records, `GET /attendance` is extremely slow, high memory usage, and Python process may OOM. | Changed to MongoDB-side `.sort().skip().limit()` with a separate `count_documents()` for the total. |
| 28 | `list_attendance()` L145 | Python `sort(key=lambda d: d["date"], reverse=True)` — sorts only by date descending, no `emp_code` tie-break. Non-deterministic ordering within the same date. | Two records on the same date appear in random order across requests. Contract requires `date desc, emp_code asc`. | Used MongoDB `.sort([("date", DESCENDING), ("emp_code", ASCENDING)])`. |
| 29 | `list_attendance()` L149 | `d["id"] = str(d.pop("_id"))` — leaks an `id` field in each attendance record. Contract says no `_id` or `id`. | Response items contain `"id": "66a..."`. | Removed. Used `find(q, {"_id": 0})` and `format_attendance_record()`. |
| 30 | `list_attendance()` | Returns raw BSON datetimes for `punch_in`, `punch_out`, and `history[].at`. Contract requires epoch milliseconds (integers). | `"punch_in": "2026-07-06T03:58:00Z"` instead of `"punch_in": 1783310280000`. | `format_attendance_record()` converts all datetime fields to epoch ms via `dt_to_epoch_ms()`, including nested history entries. |
| 31 | `list_attendance()` | No validation that `date_from <= date_to`. Reversed ranges return wrong or empty results silently. | `GET /attendance?date_from=2026-07-08&date_to=2026-07-06` returns 200 with 0 results instead of 422. | Added check: `if date_from > date_to: raise RequestValidationError(...)`. |
| 32 | `list_attendance()` | No bounds checking on `page` or `page_size`. Same issue as list_employees. | `GET /attendance?page_size=200` returns 200 instead of 422. | Used `Query(default=1, ge=1)` and `Query(default=20, ge=1, le=100)`. |
| 33 | `list_attendance()` | Missing legacy field defaults: seeded records may lack `history`, `half_day`, `late_minutes`, `overtime_minutes`. Returns `null` or omits them. | Legacy record (sample #9) has no `half_day` or `history` fields — response is missing required fields. | `format_attendance_record()` defaults: `history → []`, `half_day → False`, `late_minutes → 0`, `overtime_minutes → 0`. |
